# Mirror doctrine — session scripts, 40% audit, cookie-jar ledger, callus schedule

Homage reference built on the published doctrine of *Can't Hurt Me* and *Never Finished*
(Goggins) [snippet-only]; translated to project work. No affiliation or endorsement.

Contents: §1 Accountability Mirror script · §2 The 40% audit worksheet · §3 Cookie-jar
ledger format · §4 Callus-schedule patterns · §5 Finish protocol · §6 Voice card

## §1 Accountability Mirror script

1. The user states the status as they'd report it upward.
2. The Mirror strips it: every softener ("slightly," "mostly on track," "some
   challenges") is removed and replaced with the number and the date. "Mostly on track"
   becomes "late by N days on X; untouched for M days."
3. Controllable vs systemic split: one column each. Systemic items get a system fix WITH
   a named driver (who is pushing the fix, by when). Controllables get the next play.
4. The post-it: ONE next milestone, concrete, dated, small enough to hit within a week.
   Where will it be seen daily?
5. Close: read the stripped status aloud once. That's the sentence that goes in the next
   status report — watermelon reporting ends here.

## §2 The 40% audit worksheet

Run when "we're done," "we can't," or "impossible" is on the table:

| Question | Evidence required |
|---|---|
| What EXACTLY is being declared impossible? | The specific scope, not the vibe |
| When did we last say this? | Cookie-jar entries with dates |
| What did that actually take? | Hours/days/people from the ledger, not memory |
| What's genuinely different this time? | Named deltas (scope, people, constraint) |
| What would 10% more look like? | The next concrete rep, not "try harder" |
| Is the tank actually empty? | If the evidence says yes — SAY YES. That is also the mirror. |

Output: either a revised "here's the next rep" plan, or an evidence-backed "we stop /
we descope / we escalate" — both are honest ends. Bravado is not an output.

## §3 Cookie-jar ledger format

A ledger, not a mood board. One line per entry:

```
DATE | THE WIN | WHAT IT TOOK | THE MOMENT IT ALMOST DIDN'T HAPPEN
2026-07 | 276-test hardening week shipped | 6 days, 3 adversary rounds | the money-parser regression at day 4
2026-08 | six-skill wave built in one session | 7 parallel agents, 2 truncated specs | the mid-wave branch collision
```

Uses: drawn on mid-crisis (read the closest-matching entry aloud); fed to
`decision-science-skills:reference-class-forecasting` as the personal reference class
(what deliveries of this shape actually took); reviewed when the 40% audit asks "when
did we last say this?"

## §4 Callus-schedule patterns

- **Avoided-task-first**: the task not opened in N days goes first tomorrow, before
  email, timeboxed to one honest hour. Repeat daily until dead. The all-day tax of
  avoidance is usually bigger than the task.
- **Rehearse the feared thing**: the scenario being dreaded gets a drill instead
  (`decision-science-skills:tabletop-wargaming`); dread converts to reps.
- **The uncomfortable call before the comfortable email**: once per day, the
  highest-friction communication goes first and by the more direct channel.
- **One rep past done-enough**: when the task is "done enough," do exactly one more
  quality rep (the test, the doc line, the edge case) — the compounding habit, bounded
  so it never becomes gold-plating.

## §5 Finish protocol

1. Restate the definition of done from before fatigue set in (or write it now, once).
2. List every shortcut already taken; each is either formally accepted (written, owned)
   or scheduled for repair — no silent debt.
3. The last 10% gets enumerated as tasks — "polish" is not a task — and finished before
   anything new starts.
4. Ship, log the cookie-jar entry, THEN rest. The entry is part of finishing.

## §6 Voice card

Intense, short, second person. Names the gap without softeners; never names the user's
worth. No profanity, no humiliation, no health or fitness advice, ever. "Stay hard"
lands as the sign-off after the plan exists — never as a substitute for one. Effort aims
at controllables; system problems get system fixes with named drivers. Sustainable pace
is respected: the doctrine is finishing what was started, not working without end.
