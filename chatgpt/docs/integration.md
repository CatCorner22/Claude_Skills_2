# Ownership and existing custom workflows

The adaptation preserves these responsibilities:

| Workflow | Responsibility |
| --- | --- |
| Maximum-Delegation Auditor | Capability discovery, all feasible assistant work, permission boundaries, verification, durable saving, delivery, honest status. |
| Puppet Master | Batch independence, sufficient reads, compact briefs, useful workers, evidence-preserving output, honest cost audit. |
| Project Manager and QC | Long-work ledger and amendments, checkpoints, independent review where required, complete category sweep. |
| Creative Workaround Genius | Permitted obstacle recovery, identity checks, no control bypass or avoidable user homework. |
| Cursor selector / domain skills | Full selected workflow and sources, manual activation, compatibility contract, domain checks, stop on topic change. |

Two reciprocal changes were prepared in the existing Work skill workspace:

1. Maximum-Delegation Auditor receives a short “Work with Puppet Master” section.
   It distinguishes assistant ownership from subagent allocation and preserves
   evidence, read-back, permission, and installation limits. Companions are loaded
   only when relevant; previously read current instructions are not recursively
   reloaded.
2. Cursor Skills receives a paragraph in “Working posture and boundaries.”
   Puppet Master may optimize the execution path, but the selector still reads
   selected full workflows, compatibility contracts, and required source resources.
   It preserves manual/topic-change rules and does not load all 189 workflows.

These existing skills remain separately maintained; this repository does not
publish copies of their complete personalized instructions. The portable adapters
refer to them by skill name, not an account-specific package ID. They work with
the actual available version, and do not claim an inaccessible skill was read.

The exact reciprocal additions are retained as name-based patches for
[Maximum-Delegation Auditor](../integration/maximum-delegation-auditor.patch) and
[Cursor Skills](../integration/cursor-skills.patch). An assistant applying them
must resolve the actual current skill root and check context before mutation.
They preserve the local integration changes despite the native save failure
recorded in the validation report; their presence does not install them.

Current user instructions and host rules govern delegation and authority. The
original upstream recommendation to reduce worker count does not override a
host's requirement for useful proactive delegation. Conversely, assistant ownership
does not mean every tiny step needs a new worker. Use an exposed fresh reviewer
when required; a second pass in the same context is self-review, not independence.

If no workers exist, do feasible work directly. If no tools exist, use supplied
evidence conversationally and disclose the precise action/verification gap.
Skill text does not create a tool, connection, permission, background process,
native registration, or installation on other accounts/devices.
