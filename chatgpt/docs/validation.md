Cases A–C inputs and final evidence are retained in
[synthetic fixtures](../evals/fixtures/). Case C includes the initial defective
draft separately so a future test can rebuild that starting state. D is a
controlled hypothetical capability inventory after skill reading, not an actual
probe of a different account's tools or permissions. Its request/output are saved
alongside those fixtures. No case performed external mutations.

Efficiency observations were qualitative: bounded task-local reads, appropriate
inline work, manifest-based recovery, dependency-respecting writes/read-back, and
one independent QC worker for a task requiring it. The fresh-review case required
documentation corrections and a recheck; that work is retained, not hidden as
zero-cost. No whole-run tool-call count, token usage, price, worker startup cost,
or latency comparison was measured. No ChatGPT savings percentage or quality
equivalence claim follows from these passes.

## Honest limits

The initial bulk native Work save returned HTTP 422, and its remote read-back
showed no change. A subsequent retry saved one new skill per push through the
same documented workflow. Puppet Master, Project Manager and QC, and Creative
Workaround Genius were then assigned native skill identities. Fresh remote
snapshots confirmed that the instruction, license, script, and reference bytes
match the validated adapters. The host normalized UI YAML and generated icons;
its parsed interface fields retain the intended names, descriptions, and prompts,
with ChatGPT included in the native product metadata.

The reciprocal Auditor and Cursor-selector additions were also saved and read
back. These checks establish native persistence of the three skill packages and
the existing-skill updates in this user's ChatGPT skills workspace. They do not
establish automatic routing in every future session or account-wide activation.
The current conversation's cached skill catalog was not a reliable freshness
check. No native plugin installation or new token-savings result is claimed.

- Four representative cases are not a comprehensive or statistical validation of
  all future workflows; no randomized/matched baseline arm was run.
- Explicit skill-path invocation tests instructions after selection. It does not
  prove automatic routing, registration, account-wide installation, or behavior in
  every future ChatGPT/Work session.
- Worker reporting and fixture hashes support the observed local scope. Current
  bytes alone cannot independently prove every prior action or pre-edit state.
- The ledger fixture does not test conflicting duplicates or non-Z timestamps;
  no general transformation program is shipped by that case.
- Audit totals cover supplied normalized metadata. Hidden context, absent worker
  usage, unknown rates, tool charges, and subscription billing stay outside them.

See the [portability reference](../skills/puppet-master/references/portability.md)
for the upstream benchmark's initial citation regression, rounded means, workload
count inconsistency, and missing distribution/uncertainty data.
