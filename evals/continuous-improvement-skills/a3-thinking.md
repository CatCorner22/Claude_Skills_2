# Evals — continuous-improvement-skills:a3-thinking

## 1. Positive trigger (should load the skill)
> "I need to propose a fix for our slow request-intake process to my director and get buy-in
> from the two teams it touches. Can you help me put it on a one-page A3 with the PDCA story?"

Expected: skill loads; walks the A3 boxes in order — background, current condition with data
(robust summaries on skewed data, e.g. median wait), measurable dated target, verified root
cause, countermeasures that each trace to a named cause, an owned/dated implementation plan,
and a follow-up/check left partly blank for actual results; maps them to PDCA; keeps it to
one page; and plans a nemawashi round — walking the draft past the affected people before
any formal review — rather than unveiling a finished document.

## 2. Near-miss (should NOT load this skill)
> "Help me actually run the 5 Whys and build a fishbone to pin down why requests get assigned
> late."

Expected: this is the deep cause-analysis work that feeds an A3's analysis box, handled by
`continuous-improvement-skills:root-cause-analysis`. The A3 is the one-page story around it.
If a3-thinking loads instead, tighten the cross-links.

## 2b. Near-miss (measured-project guard)
> "We need a formal improvement project on our error rate — baseline measurement, verified
> causes, a control plan, tollgates, the works."

Expected: a full measured project with baselines and controls is
`continuous-improvement-skills:dmaic-problem-solving`; an A3 may *summarize* it, but the
project structure isn't this skill. If a3-thinking loads as the primary skill, tighten the
seam.

## 3. Quality rubric
A good response:
- **Does the task:** produces a single-page A3 with background, data-backed current
  condition, measurable dated target, verified root cause, cause-traceable countermeasures,
  a single-owner dated implementation plan, and a checkable follow-up promise — mapped to
  Plan-Do-Check-Act — plus a concrete nemawashi plan (who to walk the draft past, in what
  order).
- **Teaches:** explains *why* the A3 is a thinking and alignment tool (the value is the
  dialogue it forces), why the one-page limit is a discipline not a format, why every
  countermeasure must trace to a cause, and why consensus is built in the draft rounds, not
  the meeting.
- **Grounded and honest:** insists on data in the current-condition box; treats Check/Act as
  boxes filled in later with real results (a learning loop, not a frozen proposal); gets the
  canon right — Toyota practice codified by Sobek & Smalley and Shook, PDCA from
  Shewhart/Deming (with Deming's PDSA refinement), the fax-machine origin story flagged as
  lore — and invents no statistics; any example numbers are labeled illustrative.
- **Routes at the seams:** cause hunt → root-cause-analysis; measured project →
  dmaic-problem-solving; picking the problem across a whole stream → value-stream-mapping;
  team-designed countermeasures → kaizen-and-codesign; standardizing the win → standard-work.
