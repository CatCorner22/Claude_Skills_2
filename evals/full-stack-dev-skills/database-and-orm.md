# Evals — full-stack-dev-skills:database-and-orm

## 1. Positive trigger (should load the skill)
> "Our invoices list endpoint takes 8 seconds in production but is instant locally, and our
> dev database schema doesn't match prod anymore. Fix the data layer."

Expected: skill loads; diagnoses N+1 via the SQL log and fixes with
`selectinload`/`joinedload` or column selects; restores Alembic as the only schema-change
path (dev drift = hand-edited schema); checks indexes from evidence; puts the commit for each
use case inside the request handler/service rather than in the `get_db` teardown.

## 1b. Positive trigger (the switch-day path)
> "We built on SQLite and we're moving to Postgres this week. The load keeps failing on
> invoices, and once we had it running staging threw `too many connections`. What do we need to
> get right?"

Expected: skill loads; names the two silent SQLite differences first — foreign keys unenforced
without `PRAGMA foreign_keys=ON` per connection (so orphan rows already exist and must be found
with a `LEFT JOIN … IS NULL` sweep before the load) and money `Decimal` columns having gone
through a float on SQLite; then sizes the pool — `(pool_size + max_overflow) × workers` against
the server's `max_connections`, `pool_pre_ping` for stale idle connections, `pool_recycle`,
`NullPool` if PgBouncer or serverless is in the path. Does **not** simply say "change the URL,
the ORM makes it portable."

## 2. Near-miss (should NOT load this skill)
> "Write a SQL query joining these two CSV exports to find unmatched payments."

Expected: analytical SQL over files — `data-tools-skills:duckdb-local-analytics` /
`data-analytics-bi-skills:sql-for-analysts`. If this skill loads, sharpen the app-data-layer
framing.

## 3. Quality rubric
A good response:
- **Does the task:** N+1 identified and fixed at the query, migration discipline restored,
  constraints in the schema *with* the SQLite pragma that makes them real, money resolved to
  integer minor units (or `Numeric(p, s)` on a Postgres-only path — never a bare
  `Mapped[Decimal]` when SQLite is in the path), the commit inside the request, pool sized
  against the server.
- **Teaches:** why DB mistakes are permanent (constraints as rules that outlive code),
  migrations as one-way doors, how ORMs hide the SQL that N+1s, and why a promise the engine
  doesn't enforce reads exactly like one it does.
- **Has a failure envelope:** states where its own advice breaks — SQLite's per-connection FK
  pragma, the float path under `Decimal`, dependency teardown running after the response — and
  gives a cheap way to check each on the reader's own engine and framework version rather than
  asserting the behavior.
- **Safe:** reads autogenerated migrations before applying, never floats for money, no
  mid-service commits, no commit in the `get_db` teardown.

## 4. Anti-pattern the skill must not reproduce
A response that states `foreign keys always` or `money as Decimal` as house doctrine while
recommending SQLite first, with no mention of the pragma or the float conversion, has failed
this eval even if every line of code it wrote runs.
